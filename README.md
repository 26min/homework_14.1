
В основе проекта лежит ООП (объектно-ориентированное программирование) модель для управления каталогом товаров. Программа читает данные из JSON-файла и преобразует их в связанные между собой объекты.

### 1. Класс `Product`
Отвечает за отдельную единицу товара в магазине.
- **Основные атрибуты:**
  - `name` (str): Название товара.
  - `description` (str): Подробное описание характеристик.
  - `price` (float): Стоимость товара.
  - `quantity` (int): Количество товара в наличии.

### 2. Класс `Category`
Группирует товары по типам и хранит общую статистику по магазину.
- **Основные атрибуты:**
  - `name` (str): Название категории.
  - `description` (str): Описание категории.
  - `products` (list): Список объектов класса `Product`, входящих в эту категорию.
- **Статические атрибуты (Счетчики):**
  - `category_count`: Общее количество созданных категорий за всё время работы программы.
  - `product_count`: Общее количество уникальных товаров во всех категориях суммарно.

### 3. Модуль загрузки данных (`src/utils.py`)
Обеспечивает связь между файлами данных и ООП-моделью:
1. Функция `read_json` безопасно загружает структуру данных из файла `products.json`.
2. Функция `create_objects_from_json` циклически обходит дерево JSON, сначала инициализируя объекты `Product`, а затем передает их списком в конструктор соответствующей `Category`.

## Демонстрация структуры данных (JSON)

Программа ожидает на вход файл следующего формата:
```json
[
  {
    "name": "Смартфоны",
    "description": "Смартфоны, как средство не только коммуникации, но и получение дополнительных функций для удобства жизни",
    "products": [
      {
        "name": "Samsung Galaxy C23 Ultra",
        "description": "256GB, Серый цвет, 200MP камера",
        "price": 180000.0,
        "quantity": 5
      }
    ]
  }
]
```

### Как это выглядит в коде

При запуске главного модуля `utils.py` вы увидите список воссозданных объектов:
```bash
poetry run python src/utils.py
# Вывод: [<src.product.Product object at 0x...>, ...]
```

###  Безопасность и строгая валидация

В проект добавлены строгие проверки для защиты данных от ошибок и некорректных типов:
* **Валидация при добавлении в категорию**: Метод `add_product` в классе `Category` использует функцию `isinstance`. Это исключает возможность добавления в список товаров любых сторонних объектов (например, строк или чисел), кроме экземпляров класса `Product` и его наследников (`Smartphone`, `LawnGrass`).
* **Ограничение сложения товаров**: Перегруженный оператор `__add__` защищен строгой проверкой типов (`type`). Теперь складывать можно только товары одного и того же класса. Попытка сложить разные категории (например, смартфон и газонную траву) безопасно вызывает исключение `TypeError`.

### Обработка ошибок при введении нулевого или отрицательного количества товаров

В проект добавлена обработка ошибки для избежания остановки программы. 
При некорректном вводе пользователь увидит ошибку и сможет ее исправить.
```
if quantity > 0:
    self.quantity = quantity
else:
    raise ValueError("Товар с нулевым количеством не может быть добавлен")
```


### Подсчет среднего ценника

В классе `Category` реализован метод, который подсчитывает средний ценник всех товаров. При попытке деления на ноль программа обработает этот сценарий и вернёт "0".
```
    def middle_price(self):
        try:
            return sum([product.price for product in self.__products]) / len(self.__products)
        except ZeroDivisionError:
            return 0
```
